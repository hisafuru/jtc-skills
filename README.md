## 結論

- **AIに「JTCの優秀な部下」の判断様式を持たせるための4つのスキルセットである**：着手前の目的確認、自分で決めるか相談するかの切り分け、文書の書き方、チャットでの報告の型を、それぞれ独立したタイミングで発動するスキルに分けている
- **導入は`skills/`配下の4フォルダを、利用環境のスキルディレクトリにコピーするだけで完了する**
- **4つは互いに役割が異なり、重複しない**：発動タイミング（着手前／着手時／文書作成時／報告時）で分割している

## 1. このスキル群について

「JTCの優秀な部下」とは、新人のように何でも確認するわけでも、管理職のように全権を持つわけでもない、委ねられた範囲は自分で判断し、上には結論だけを持っていくという中堅社員の判断様式を指す。このスキル群は、その判断様式をAIエージェントに移植するために作られた。

分割の軸はタスクの時系列である。AIがそのタイミングで実際に読むべきものとして発動する必要があるため、着手前・着手時・文書作成時・報告時の4つに分けている。

判断の基準を扱う`jtc-report-escalate`を「迷ったとき」ではなく「着手時」に置いているのは意図的である。迷っていると気づくための基準がスキルの中にある以上、迷ってから読む設計では発動しない。作業に入る前に基準を持たせる必要がある。

## 2. 収録スキル一覧

| スキル名 | 発動タイミング | 一言概要 |
|---|---|---|
| `jtc-scope-check` | タスク着手前 | 指示された前提を鵜呑みにせず、本当のゴールを確認してから始める |
| `jtc-report-escalate` | タスク着手時 | 調べれば分かることは調べ、相手の頭の中にしかないことは聞く |
| `jtc-readable-md` | ドキュメント作成・修正時 | 結論を先頭に置き、本質的な原因で構造化する書き方の規約 |
| `jtc-report-brief` | チャットでまとまった内容を返すとき | 30秒概要＋3分詳細に分け、報告と判断依頼を分けて示す |

`jtc-report-brief`は、報告の中身を【📢報告】（伝えるだけ）と【❗️判断依頼】（相手の判断が要る）に分け、判断依頼には番号を振る。読み手が「1はこう進めて、2は保留」と番号で返せる状態にするためである。

## 3. 導入方法

1. `skills/`配下の4フォルダ（`jtc-scope-check`、`jtc-readable-md`、`jtc-report-brief`、`jtc-report-escalate`）を、利用環境のスキルディレクトリにそのままコピーする
2. 各フォルダの`SKILL.md`が自動的に読み込まれ、`description`に書かれた条件に該当する場面で発動する
3. 4つすべてを入れる必要はない。必要なものだけを選んで導入してよい。ただし`jtc-scope-check`と`jtc-report-escalate`はセットでの導入を推奨する（理由は4章に記載する）

## 4. 使う上での注意

- `jtc-scope-check`は、グラフ作成や資料作成のような成果物系のスキルと同時に適用範囲が重なることがある。着手前の目的確認を優先させたい場合は、他のスキルより先に検討されるよう環境側の設定を確認すること
- **`jtc-scope-check`は本文の末尾で`jtc-report-escalate`の読み込みを指示している**。スコープの合意ができた時点で判断基準を持たせるための導線であり、`jtc-scope-check`だけを導入すると指示先が存在しない状態になる。片方だけ入れる場合は、この1行を削るか読み替えること
- 4つは同じ「JTCの優秀な部下」という人格を前提に書かれている。一部だけを導入しても各スキルは独立して動作するが、人格の一貫性は薄れる
