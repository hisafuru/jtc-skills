## 結論

- **AIに「JTCの優秀な部下」の判断様式を持たせるための4つのスキルセットである**：着手前の目的確認、文書の書き方、チャットでの報告の型、迷ったときの相談と完了報告を、それぞれ独立したタイミングで発動するスキルに分けている
- **導入は`skills/`配下の4フォルダを、利用環境のスキルディレクトリにコピーするだけで完了する**
- **4つは互いに役割が異なり、重複しない**：発動タイミング（着手前／文書作成時／チャット報告時／判断に迷ったとき）で分割している

## 1. このスキル群について

「JTCの優秀な部下」とは、新人のように何でも確認するわけでも、管理職のように全権を持つわけでもない、委ねられた範囲は自分で判断し、上には結論だけを持っていくという中堅社員の判断様式を指す。このスキル群は、その判断様式をAIエージェントに移植するために作られた。

分割の軸はタスクの時系列である。AIがそのタイミングで実際に読むべきものとして発動する必要があるため、着手前・文書作成時・チャット報告時・判断に迷ったときの4つに分けている。

## 2. 収録スキル一覧

| スキル名 | 発動タイミング | 一言概要 |
|---|---|---|
| `jtc-scope-check` | タスク着手前 | 指示された前提を鵜呑みにせず、本当のゴールを確認してから始める |
| `jtc-readable-md` | ドキュメント作成・修正時 | 結論を先頭に置き、本質的な原因で構造化する書き方の規約 |
| `jtc-report-brief` | チャットでの完了・進捗報告時 | 30秒概要＋3分詳細に分け、初見の相手にも通じる平易な言葉で書く |
| `jtc-report-escalate` | 判断に迷ったとき・完了時 | 自分で決めてよい範囲は決め切り、悪い情報ほど早く伝える |

## 3. 導入方法

1. `skills/`配下の4フォルダ（`jtc-scope-check`、`jtc-readable-md`、`jtc-report-brief`、`jtc-report-escalate`）を、利用環境のスキルディレクトリにそのままコピーする
2. 各フォルダの`SKILL.md`が自動的に読み込まれ、`description`に書かれた条件に該当する場面で発動する
3. 4つすべてを入れる必要はない。必要なものだけを選んで導入してよい

## 4. 使う上での注意

- `jtc-scope-check`は、グラフ作成や資料作成のような成果物系のスキルと同時に適用範囲が重なることがある。着手前の目的確認を優先させたい場合は、他のスキルより先に検討されるよう環境側の設定を確認すること
- 4つは同じ「JTCの優秀な部下」という人格を前提に書かれているため、一部だけを導入する場合も、残したスキルの`description`内にある他スキルへの参照（役割分担の説明）が浮いた記述にならないか確認すること
